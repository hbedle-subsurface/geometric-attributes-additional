Coherence and curvature answer one kind of question. These four programs answer the others.

Is this reflector broken, and is it bent? Those two questions cover a great deal of structural interpretation, and the first set of modules is about how they get answered. They leave out a lot. How do I clean the volume up without flattening the faults I am looking for? How much should I trust this pick? What does this package look like, as a pattern rather than as a set of amplitudes? Are these reflectors even parallel to each other?

Six modules on four AASPI programs — sof3d, disorder, glcm3d and nonparallelism. Build the data, watch the attribute being computed on it, move the parameters that are usually left at their defaults, and read the numbers off the running page. There is nothing to install.

What you need first. Written for undergraduate geology and geophysics students. You should know what a seismic trace is, what a reflector is, and roughly what dip and coherence are — the first set covers those from the beginning if you do not. Everything after that is built up in order inside the modules.

Filtering is an interpretation

Structure-oriented filtering decides what in your data is noise. Everything downstream inherits that decision, and the only way to check it is to look at what the filter threw away.

Not everything worth finding is an edge

Coherence is built to find discontinuities. Chaos, poor data quality and non-parallel bedding are none of those, and they need attributes that ask a different question.

Some of these are not for looking at

Texture attributes are built to be fed to a classifier. Judging them by whether the section looks good is judging them by the wrong criterion, and the documentation says so.

The modules

In the order they build on each other. The first two are a pair, and so are the fourth and fifth. Work through them in sequence and you should be able to say what each program measures and why someone would run it, name the parameter that most changes the answer, tell which attributes are telling you the same thing twice, and give more than one explanation for any anomaly you see.

01

Filtering along structure

Five filters over the same window of data, and one decision that matters more than the choice between them: which direction to average in. Mean, alpha-trimmed, median, LUM and principal component, with the error of each measured against a clean model.

02

Edge-preserving filtering

Every filter in module 01 smooths a fault away as happily as it smooths a reflector. Two fixes: move the window off the edge, or refuse to filter where coherence says there is one. Both, with the damage measured.

03

Disorder

A second difference in all three directions, divided by the energy in the window. It ignores faults on purpose and finds the places where the data are too messy to pick — which turns a structure map into a structure map with error bars.

04

The co-occurrence matrix

Texture starts by throwing the amplitudes away and keeping only their rank, then tallying which level sits next to which. Quantization, the 1.5σ clip, four directions, and why the matrix is nearly always too sparse for comfort.

05

The texture measures

Contrast, dissimilarity, homogeneity, energy, entropy, mean, variance and correlation. Where GLCM energy has nothing to do with amplitude, where GLCM variance turns out to be semblance, and how few of the eight are saying different things.

06

Nonparallelism

Turn every dip into an arrow and measure how much the arrows in a window disagree. Salt, mass transport complexes and karst fail that test while often passing coherence, and a channel with no structural expression fails a different one.

What this is, and what it is not

These modules are teaching models, built to make ideas visible. The algorithms follow the AASPI documentation, but they run on small synthetic datasets, in two dimensions, and in their plain brute-force form, so the method can be read and watched rather than assumed. Every module has a Method tab listing what it has simplified and why.

Every number quoted in the text is measured from the page you are looking at, not estimated. Move a slider and the numbers in the prose move with it — including, in a couple of places, past the point where the conclusion in the text still holds. Those places are marked, because noticing them is the more useful skill.

This is not attribute software. For production work on real volumes, use AASPI or your interpretation package. The numbers here describe the model on the screen, not your survey.

About

Built for teaching by Heather Bedle, School of Geosciences, University of Oklahoma, with the Attribute Assisted Seismic Processing and Interpretation (AASPI) consortium.

A companion to How Geometric Attributes Actually Work, which covers dip, coherence, curvature and aberrancy. This set takes four more AASPI programs that sit alongside those: the filtering that usually runs before them, and three attributes that measure things coherence and curvature were never built to see.

Everything runs in the browser. No installation and no account. Nothing you do inside a module — no slider, no click, no trace you generate — is transmitted anywhere. The module code makes no network requests of its own.

The one request each page does make is a page-view count, which records that the page was opened and nothing else: no cookie, no account, nothing about you. I keep that count for two reasons — so the modules people actually use are the ones that get improved, and so I can show my university that you all are using these, which is how they keep getting built.
